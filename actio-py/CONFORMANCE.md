# Conformance — actio-py

Row by row: what the protocol requires, where this tree implements it, and the test that proves it.

- The normative statement is the protocol's own MUST/SHOULD, quoted or paraphrased with its
  location in `../doc/actio_protocol.md` (`doc L…`). Where the plan made a choice the protocol
  leaves open, the decision is cited as `D-x`.
- The implementation cell names the file and function in `src/actio/` that carries the rule.
- The tests cell names the rows that would fail if the rule broke:
  `unit:` a unit test in `tests/`, `agent:` a test driving a live `ActioAgent`,
  `e2e:` a two-agent scenario in `tests/test_e2e.py`, `interop:` a cross-implementation run in
  `interop/test_interop.py` (needs the TS reference at `../actio-ts` and its npm dependencies),
  `vectors:` a case in `tests/vectors/<kind>/`, driven by `tests/test_vectors.py`.
- A row that no test in this tree exercises says `no unit test` and names what covers it.

## Differences from actio-ts

Where the two projects differ on purpose, cited by the decision (the README defines them):

- D-18: the B2 watch belongs to the exchange — the exchange subscribes to the destination inbox before it writes the request and releases the watch when it settles, as in `actio-go` — where the reference keeps a per-destination watcher with reference counts.
- D-22, D-23: the watchdog events only wake the folder's subscribers, and a 5 s audit re-stats the folders — a safety net the reference (fsnotify) does not need, because watchdog hides what fsnotify reports.
- D-24: the `announce` diarium line is written before the announce file; the reference writes the file first.
- D-9: at stop, the answered exchanges wait up to 1 s for their confirmation before the archive, so a code-300 exchange ends `confirmed` or `completed`; the reference archives at once.
- D-10: the `restart` `delay` is clamped at 60 s; the reference's delay is unbounded.
- D-15: a rejection's reason is one line of at most 200 characters from one function, built from the path and the schema, never from the value; the reference's reasons quote the schema library's wording. Its malformed-JSON wording is matched by context: an inbox file of the exchange's own carries the parser's error, while a peer's publication in a scan and a diarium line get the flat `not valid JSON`, as the reference's do.
- D-19: the capability schemas are compiled with `jsonschema`, not Ajv: an unknown keyword in our own capability is a registration error, and Ajv's `strictTypes`/`strictRequired` are not ported.
- Strict UTF-8: a file with an invalid byte is ignored where the reference decodes it as U+FFFD.
- Duplicate attachment basenames are refused; the reference lets the later copy win.
- A handler that will not stop is left to end on its own after 1 s, with one log line: the one exception to "nothing armed".
- The API surface is asyncio: `wait_stopped()`, `async with agent`, the decorator form of `capability`/`on_command`, durations in seconds, `ActioError` a `ValueError` below 1000; and the two named thread pools (asyncio's default executor and `actio-io`) are the only module state in `src/`.
